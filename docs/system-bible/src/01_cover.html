Before you start

How to read this document

This is a behavioral reference, not API documentation. It explains what the system does, why it does it, and what happens in every scenario — in plain language. You should be able to understand SmartTriage completely without opening the code. When the code enforces an exact number (a threshold, a time limit, a dose cap), that number is printed here in monospace so you know it is the real value, not an approximation.

Tip

New to the project? Read Chapter 1 (the big picture), Chapter 2 (who can do what), and Chapter 3 (one patient’s journey end-to-end) in order — about 20 minutes — and you will understand 80% of the system. Every other chapter is a deep dive you can read on demand.

The building blocks used on every page

Note

Background information and context — why something is designed the way it is.

Business rule

A hard rule the server enforces. These cannot be bypassed from the user interface.

Warning

A behavior that surprises people, or an easy mistake with real consequences.

Patient safety

A rule that exists to protect patients. Treat these as inviolable when changing code.

Tip

A shortcut or best practice that makes daily use easier.

Needs clarification

Something the code leaves ambiguous or that the team should decide explicitly. All of these are also collected in Appendix C.

Conventions

  • Roles appear as chips: DOCTOR NURSE REGISTRAR. When a rule names roles, those are the only roles allowed — everyone else receives a “403 Forbidden” response.
  • Cross-references look like §8.2 — chapter § section. The Table of Contents lists page numbers for both.
  • Lifecycles (a record’s allowed states, e.g. a lab order moving from ordered to resulted) are drawn as flow diagrams, with green for success ends, red for failure ends.
  • “Soft delete” — SmartTriage never physically erases clinical rows. Deleting marks a record inactive (isActive=false); it disappears from lists but stays in the database and the audit trail. Assume every “delete” in this document is a soft delete unless stated otherwise.
  • Error codes — 400 invalid input · 401 not logged in · 403 not allowed · 404 not found (or another hospital's) · 409 conflict · 422 business-rule refusal. Full model: §18.
